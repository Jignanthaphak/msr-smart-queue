## วิธี deploy ขึ้น prod

1. ก๊อบไฟล์ในบันเดิลนี้ทับลงโปรเจกต์จริง (รักษาโครงสร้างโฟลเดอร์)
   - ⚠️ `app/globals.css` เป็นไฟล์ global — ถ้าไม่แน่ใจว่า prod ตรงกับ local ให้ merge เฉพาะส่วนที่เพิ่มท้ายไฟล์ (ตั้งแต่คอมเมนต์ `---------- ตัวอย่างรายงาน PDF/Word (หน้า report_pdf) ----------`)
   - ⚠️ **อย่าลืมโฟลเดอร์ `public/`** — บันเดิลนี้แถมไฟล์ฟอนต์กับพื้นหลังมาให้ด้วย เพราะเป็นสาเหตุที่รูปไม่ขึ้น/ฟอนต์เพี้ยนบนเซิร์ฟเวอร์
     - `public/fonts/THSarabunNew.ttf`
     - `public/fonts/THSarabunNew Bold.ttf` ← **ไฟล์นี้เพิ่งเริ่มใช้รอบนี้** ของเดิมไม่เคยเรียก ถ้าเซิร์ฟเวอร์ไม่มีจะได้ไฟล์ที่ภาษาอังกฤษเป็นตัวหนาใหญ่ (**ชื่อมีเว้นวรรค** ห้ามเปลี่ยน)
     - `public/images/bg-pdf/bg.png`
2. ไม่มี DB migration · ไม่มี permission ใหม่ · ไม่ต้อง `npm install`
3. rebuild:
   ```
   npm run build
   ```
   แล้ว restart (pm2 / ecosystem ตามปกติ)

### 🐞 บั๊กรอบแรก: บนเซิร์ฟเวอร์รูปไม่ขึ้น + ภาษาอังกฤษเป็นตัวหนาใหญ่ (แก้แล้ว)

**อาการ:** deploy รอบแรกขึ้น prod แล้วไฟล์ที่ได้ไม่มีพื้นหลัง และตัวอักษรภาษาอังกฤษกลายเป็นตัวหนาใหญ่ ภาษาไทยเพี้ยน

**สาเหตุ:** prod ถูก serve ใต้ subpath — `https://mhc4.dmh.go.th/msr/report/report_pdf` แต่โค้ดเรียกไฟล์ด้วย path แบบ root ตรง ๆ

```
fetch("/fonts/THSarabunNew.ttf")
  → https://mhc4.dmh.go.th/fonts/THSarabunNew.ttf     ❌ ไม่ใช่ของแอป
  → ที่ถูกต้องคือ .../msr/fonts/THSarabunNew.ttf
```

พอโหลดฟอนต์ไม่ได้ **jsPDF ไม่ throw error แต่เงียบ ๆ ไปใช้ Helvetica แทน** → Helvetica ที่ขนาด 18pt ดูใหญ่กว่า TH Sarabun ที่ 18pt มาก และภาษาไทยไม่มีใน Helvetica เลยเพี้ยน · พื้นหลังก็หายด้วยเหตุผลเดียวกัน

> เครื่อง local ไม่เจอปัญหาเพราะรันที่ root · และไฟล์ **Word** ดูเหมือนปกติเพราะ Word ใช้ฟอนต์ตามชื่อจากที่ติดตั้งในเครื่องผู้ใช้ ไม่ได้ใช้ไฟล์ที่ fetch มา (แต่พื้นหลังใน Word ก็หายเหมือนกัน)

**วิธีแก้:** ไม่ให้โค้ดพึ่งค่า config ที่อาจตั้งไม่ตรงกันระหว่างเครื่อง แต่ให้**ตรวจ prefix เองจาก URL จริงของหน้า** โดยอ่านจาก `<link>`/`<script>` ที่ Next โหลดไว้

```js
// /msr/_next/static/chunks/abc.css  →  prefix = "/msr"
// /_next/static/chunks/abc.css      →  prefix = ""
```

แล้วไล่ลอง `prefix ที่ตรวจได้` → `clientConfig.base_path` → `""` จนกว่าจะได้ไฟล์จริง พร้อมเช็ค HTTP status และ content-type กันไม่ให้เอาหน้า 404 HTML ไปทำเป็นฟอนต์

**พฤติกรรมเมื่อโหลดไม่ได้ ไม่เงียบอีกต่อไป:**

| โหลดไม่ได้ | ผลลัพธ์ |
|-----------|---------|
| ฟอนต์ตัวปกติ | **หยุดและขึ้น error บอก URL ที่ล้มเหลว** ไม่ปล่อยไฟล์เสียออกมา |
| ฟอนต์ตัวหนา | ใช้ตัวปกติแทน (หัวเรื่องไม่หนา แต่ภาษาไทยยังถูก) + `console.warn` |
| พื้นหลัง | ออกรายงานต่อได้โดยไม่มีพื้นหลัง + `console.warn` |

**หน้าพรีวิวบนเว็บ** ก็ย้ายจาก `@font-face` ใน CSS มาลงทะเบียนด้วย **FontFace API** ตอน runtime แทน เพราะ `url()` ใน CSS ใส่ prefix ของ subpath ไม่ได้

> `config/Client.js` → `base_path` บน prod ควรเป็น `"/msr"` เพื่อให้รูปส่วนอื่นของแอปถูกต้อง — แต่หน้า report_pdf ไม่พึ่งค่านี้แล้ว ทำงานได้ไม่ว่าค่าจะตั้งไว้ยังไง

ถ้ายังเจอปัญหา เปิด DevTools → Network ตอนกด Export จะเห็น URL ที่ล้มเหลวตรง ๆ
